# 코바 전략실 첫 버전

기존 Buzz 직원 로그인과 NIP-42 채널 권한을 사용하는 `/chat/strategy.html` 화면.
새 인증 키나 메일 비밀번호를 만들지 않으며 클라이언트는 메일 수집 서비스의
비밀 정보에 접근하지 않는다. 사용자는 코바 메일연동 채널에 접근 가능해야 한다.

## 데이터 계약

- 설치된 수집기 공개키와 코바 채널에 일치하는 서명된 kind 9 메일만 읽는다.
- 메일 본문의 원본 날짜(한국 시간)로 집계하며 relay 수집 시각을 대신 쓰지 않는다.
- 제목 규칙 분류는 고유 요청/거래 판정이 아니다. 수신·발신 겸용 메일도 수신 집계에 포함한다.
- 월 비교는 이번 달과 지난달의 동일 경과 일수. 말일 차이는 양쪽을 짧은 기간에 맞춘다.
- 본문에서 일정 단어와 함께 나온 명시적 YYYY-MM-DD 날짜는 **미확인 후보**다.
  인용된 과거 메일 날짜가 포함될 수 있으므로 확인 없이 업무나 입고 확정으로 저장하지 않는다.
- 첨부 PDF 내용, 운송사 실시간 상태, 고유 거래 연결, 응답시간/수주율/지연율은 미구현이다.
- 초기 수집 중 집계는 잠정치다. 최대 10,000개 이벤트를 겹치는 시간 경계로 읽고,
  조회 한도·동일 초 포화는 화면에 표시한다. live 구독은 역사 조회 이전에 시작한다.
- 읽기 실패 시 수치 영역을 숨기고 명시적 오류와 새로고침을 표시한다.

## 공유 업무 기록

이 버전은 별도 relay API/새 프로토콜 연산을 추가하지 않고 **기존 채널 메시지**로
사람이 읽을 수 있는 업무 제목/날짜/상태와 완전한 JSON 스냅샷을 함께 남긴다.
kind 9 + h(코바 채널) + t(buzz-strategy-v1) + d(업무 ID). 새 프로토콜을 정의하는
범용 업무 엔진이 아닌 설치별 클라이언트 기능이며, 채널 타임라인에도 기록이 보인다.
원문 메일을 수정하지 않으며 업무 담당자 이름과 서명한 작성자를 구분한다.

작성자별 업무 ID를 사용해 타인의 동일 ID가 원래 업무를 덮어쓰지 못하게 한다.
수정 전에 최신 revision을 조회한다. 동시에 서로 다른 장치에서 저장하면 같은 revision의
스냅샷은 생성시각, 동일 초에는 작은 event ID로 결정된다. 서버 CAS 보장은 없다.
수정한 모든 스냅샷은 채널 이력에 남는다. 팀 공동 수정/충돌 병합은 다음 단계다.
전송 전 서명 이벤트를 계정/relay별 로컬 재시도 저널에 저장한다. 실패 후 재시도는
같은 ID를 쓰며 서버 확인을 받은 후에만 저널을 지운다. 불명확한 응답은 ID 조회로 확인한다.
브라우저 저장소를 삭제하면 아직 전송되지 않은 저널은 복구할 수 없다.

## 검증과 배포

repo Hermit 활성화 후 `desktop/`에서:

```sh
node --experimental-strip-types --import ./test-loader.mjs --test korean/web/strategy/model.test.mjs
pnpm exec tsc -p korean/web/tsconfig.json
pnpm exec playwright test --config korean/web/playwright.config.ts strategy.spec.ts
pnpm exec vite build --config korean/web/vite.config.ts
python3 ../scripts/deploy-strategy.py
```

일반 브라우저 전용 페이지라서 native mock bridge가 필요하지 않는다.
데스크톱 native overlay는 `node korean/check.mjs`로 별도 검증한다.

배포 스크립트는 기존 웹 채팅/로그인 서비스를 다시 빌드하거나 재시작하지 않는다.
해시된 정적 자산과 strategy.html을 추가하고 기존 index에 버전된 메뉴 링크
전략실 컴포넌트 모듈만 추가한다. index를 백업하며 기존 파일을 배포 직전 다시 비교한다.
다른 작업에서 웹 index를 새로 배포한 경우 이 스크립트를 다시 실행하면 고정 링크를 복구한다.
새로운 웹 빌드에서는 main.tsx가 같은 전략실 모듈을 불러온다. 기존 strategy.html 주소도
/chat/#strategy로 연결된다. 웹은 기존 채팅 DOM을 보존하며 오른쪽 본문에 공통 Room을
마운트하고, 채널 선택 시 원래 대화로 돌아간다. 앱은 홈 경로의 strategy 검색 상태를
사용해 같은 컴포넌트를 표시하며, Buzz 테마 토큰·사이드바 버튼·기본 탐색 기록을 따른다.
롤백은 출력된 백업 index.html을 서버 web-client/index.html에 복구한다.
native 고정 메뉴는 한국어 overlay에 포함된다. 앱은 같은 Room 컴포넌트를 오른쪽 콘텐츠 영역에
표시하고 앱의 기존 키로 NIP-42 및 업무 이벤트를 서명한다. 키를 웹으로 전달하지 않는다.
웹 전용 로그인/전역 CSS/루트 마운트는 main.tsx로 분리한다. 앱에서는 사이드바 메뉴와 기본 뒤로가기로 이동하고, 같은 relay와 채널 이력으로 웹과 동일한 지표와 업무를 표시한다.

## 사람 확인

웹 Buzz 새로고침 → 왼쪽 전략실 → 메일 검토 → 실제 업무 1건 등록 →
선택한 날짜의 캘린더에서 제목·시간·물품 확인 → 새로고침 후 유지 확인.
운영 데이터에 테스트 업무를 자동 게시하지 않는다. 브라우저 E2E는 별도 mock relay를 쓴다.
