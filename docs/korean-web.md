# 한국어 웹 메신저

접속 주소: **https://buzz.kovar.kr/chat/**. 설치 없이 PC와 휴대폰 브라우저에서
기존 Buzz 계정의 채널·개인 대화·답글을 사용합니다. 한국어/English 선택은
브라우저에 저장합니다. 기존 원본의 저장소 웹 화면과 릴레이 경로는 유지합니다.

## 아이디 로그인과 관리자 직원 발급

Windows·Mac·휴대폰 모두 위 주소에서 아이디와 비밀번호로 접속합니다.
로그인은 항상 같은 Buzz 공개 계정으로 인증합니다. 채널 참여와 기존 메시지는
기존 릴레이에서 조회하며, 새로 로그인하거나 비밀번호를 변경·초기화해도 계정을
새로 만들지 않습니다. 현재 대화 화면은 최근 이벤트 200개를 불러옵니다.
과거 메시지를 삭제하거나 다른 저장소로 이전하지 않습니다.

첫 연결만 소유자가 **관리자 최초 설정**에서 기존 소유자 `.ncryptsec` 백업,
백업 비밀번호, 새 로그인 아이디·비밀번호 및 이름을 입력합니다. 현재 릴레이의
소유자 공개키와 일치해야 합니다. 초기 설정을 두 번 수행할 수 없습니다.
이 과정은 사용자가 자신의 브라우저에서 직접 진행합니다. 키나 비밀번호를
채팅으로 보내거나 에이전트에게 전달하지 않습니다.

로그인 후 **채널 목록 → 계정 관리 → 직원 계정 발급**에서 직원 아이디·이름,
12자 이상의 초기 비밀번호와 참여할 채널을 선택합니다. 등록 상태가
**사용 가능**이 되면 직원에게 아이디와 초기 비밀번호를 전달합니다.
직원은 첫 로그인에서 본인만 아는 비밀번호로 바꾼 뒤 메시지를 보낼 수 있습니다.
처음 계정 발급에는 파일이 필요하지 않습니다.
이미 Buzz를 사용하던 직원은 **기존 직원 Buzz 계정 연결**로 원래 계정 백업을
한 번 연결해야 기존 계정의 DM·채널·프로필을 그대로 유지합니다. 기존 계정 대신
새 계정을 발급하면 이전 개인 대화 권한은 새 계정에 자동 이전되지 않습니다.

관리자는 목록에서 직원 초기 비밀번호를 재발급할 수 있습니다. 재발급은 계정
키를 바꾸지 않으며 기존 대화를 유지합니다. 원래 계정에 참여했던 채널은
삭제하지 않습니다. 직원 계정 발급은 계정·키·재시도 작업을 한 번에 저장한 뒤
원본 Nostr 9030/9000/0 이벤트로 릴레이·채널·프로필 등록을 수행합니다.
부분 실패는 같은 서명 이벤트를 재시도하고, 6회 실패 후 관리자가 **등록 재시도**를
선택할 수 있습니다. 실패 상태의 직원은 등록 완료 전 로그인할 수 없습니다.

**이 기기에서 로그인 상태 유지**를 선택하면 로그인 쿠키가 30일 유지됩니다.
선택하지 않으면 8시간 유효한 브라우저 세션 쿠키를 사용합니다.
쿠키는 Secure·HttpOnly·SameSite=Strict이고 서버에는 토큰 해시만 저장합니다.
비밀번호 변경은 다른 로그인 서비스 세션을 만료시킵니다. 현재 화면의 대화 연결은
계정 관리에서 비밀번호가 바뀐 뒤에도 동일한 계정으로 유지됩니다.

## 계정 보관 방식과 원본 업데이트

일반 로그인은 원본의 사용자가 직접 키를 관리하는 방식에 의도적으로 별도 계정
서비스를 추가합니다. 홈서버가 계정 키를 AES-256-GCM으로 암호화해 보관하고,
인증된 계정의 NIP-42 인증·채팅 이벤트를 대신 서명합니다. 홈서버 운영자를 신뢰하는
사내 사용 방식입니다. 비밀번호는 salt를 가진 scrypt 해시로 저장합니다.
키를 브라우저 저장소나 응답에 평문으로 반환하지 않습니다.

서비스는 Docker 내부에만 노출하며, HTTPS의 `/chat-api/` 경로로 접근합니다.
원본 Rust 코드·DB 스키마·권한 규칙은 바꾸지 않습니다. NIP-98을 사용하는 기존
`/query`·`/events` 경로로 릴레이를 호출합니다. 일반 로그인과 직원 발급 기능은
Windows·Mac·모바일 **웹**에 적용됩니다. 기존 Tauri·Flutter 네이티브 앱의
아이디 로그인은 이번 구현에 포함되지 않습니다.

계정 저장소는 `buzz-home_buzz-login-data` Docker 볼륨의 `accounts.json`과
`master.key`입니다. 운영 백업에는 **두 파일을 함께 포함해야 합니다**. 볼륨은
브라우저·앱 재실행, 서비스 재시작과 이미지 업데이트에도 유지됩니다.
`docker compose down -v`로 계정 볼륨을 삭제하지 마세요. 새 직원의 계정 키를
복구하려면 이 보관 자료가 필요합니다. 에이전트는 운영 계정 저장소를 열어보지 않습니다.

## 기존 백업 로그인

기존 백업과 NIP-07 확장은 접힌 **기존 백업·서명 확장으로 로그인**에서 계속
사용할 수 있습니다. 이 방식은 키를 브라우저 Worker에만 두고 로그인 서비스로
전송하지 않습니다. 개인 기기의 암호화 백업 저장도 유지합니다.
직원용 일반 로그인과 별도이며 직원이 매번 백업을 준비할 필요는 없습니다.

## 모바일 화면

- 채널 목록과 대화를 분리하고 왕복 버튼을 제공합니다.
- 터치 대상은 최소 44px이고, 입력 글자는 iOS 자동 확대를 피하는 1rem입니다.
- 화면 높이는 visualViewport를 따라 바뀌어 키보드가 열릴 때 입력 공간을 조정합니다.
- 안전 영역, 좁은 화면, 짧은 화면 및 가로 넘침을 처리합니다.
- Enter는 전송, Shift+Enter는 줄바꿈입니다. 한글 조합 중 Enter는 전송하지 않습니다.
- 이전 메시지를 읽고 있으면 새 메시지가 와도 자동으로 아래로 이동하지 않습니다.

실제 iPhone/Android의 키보드, 파일 선택 및 네트워크 전환은 사용자가 직접
확인해야 합니다. WebKit 모바일 에뮬레이션은 실제 휴대폰 테스트를 대신하지 않습니다.

## 현재 범위

지원: 기존 계정 로그인, 참여한 채널/DM 목록, 최근 이벤트 200개 조회와 실시간
수신, 한글 메시지, 답글, 기본 수정/삭제 반영, 언어 전환, 수동 재연결.

파일 업로드, 음성, 알림, 채널 생성/초대 관리, 에이전트, 포럼 작성 등은
데스크톱을 사용합니다. 데스크톱 전체 기능을 브라우저로 이식한 버전은 아닙니다.
포럼 등 미지원 유형에는 데스크톱 이용 안내를 표시합니다.

전송 전에 서명한 메시지 한 개를 탭의 sessionStorage에 기록합니다. 릴레이의
긍정 OK를 받은 뒤 기록을 지웁니다. 실패하면 동일한 ID를 재전송하며 새 메시지를
자동으로 만들어 중복시키지 않습니다. 기록은 계정과 릴레이에 묶입니다.
탭을 닫기 전에 남아 있는 재시도 메시지를 확인하세요. 브라우저 저장소 접근을
금지하면 재시도 기록을 저장할 수 없어 메시지를 보내지 않습니다.

## 구조와 원본 업데이트

모든 웹 코드/설정은 `desktop/korean/web/`에 추가했습니다. 원본 파일을
수정하거나 Tauri mock bridge를 제품에 포함하지 않습니다. Nostr의 NIP-42
인증, 서명 이벤트, d-tag 채널 메타데이터와 h-tag 메시지를 사용하며,
접근 권한은 기존 릴레이가 검사합니다. 브라우저에서는 Tauri 기능을 실행하지 않습니다. 로그인 서비스 역시 별도 폴더에 추가합니다.

원본의 제품 방향인 동일 도메인·동일 계정·동일 워크스페이스를 따르며,
원본의 저장소 웹 화면을 채팅 화면으로 대체하지 않고 `/chat/`을 추가합니다.
Git 충돌 위험은 분리했지만 원본 프로토콜이나 로그인 계약이 바뀌면 웹 코드를
검토해야 합니다. 원본 릴리즈에 웹 메신저가 자동 포함되지는 않습니다.

## 빌드·검증

저장소 루트에서 Hermit 환경을 활성화하고 고정 의존성을 설치한 뒤:

```bash
cd desktop
pnpm exec tsc -p korean/web/tsconfig.json
pnpm exec biome check korean/web
node --import ./test-loader.mjs --experimental-strip-types --test korean/web/login-service/service.test.mjs
node --import ./test-loader.mjs --experimental-strip-types --test korean/web/tests/protocol.test.mjs
pnpm exec playwright install chromium webkit
pnpm exec playwright test --config korean/web/playwright.config.ts
pnpm exec vite build --config korean/web/vite.config.ts
pnpm exec vite build --config korean/web/login-service/vite.config.ts
```

결과는 `desktop/korean/web-dist/`입니다. 원본 데스크톱의 `dist/`와 별도입니다.
테스트는 합성 계정과 테스트 릴레이로 인증·전송·실패 재시도를 검사합니다.
실제 직원 대화에 테스트 메시지를 보내지 않습니다.

배포된 HTML/JS/CSP도 같은 테스트로 확인할 수 있습니다:

```bash
BUZZ_WEB_TEST_URL=https://buzz.kovar.kr/chat/ \
  pnpm exec playwright test --config korean/web/playwright.config.ts
```

## 홈서버 배포·복구

```bash
python3 korean/web/deploy-home.py /Users/kovar/Servers/buzz
```

이 명령은 운영 서버를 변경합니다. 홈서버의 Caddyfile과 compose.home.yml을
먼저 `web-deploy-backups/`에 백업합니다. `/chat/` 정적 파일과 읽기 전용 볼륨을
추가하고 별도의 로그인 컨테이너와 계정 보관 볼륨을 구성합니다. 설정·서비스 상태 검사 후 Caddy를 재적용합니다. 릴레이·DB·S3는 재설치하지 않습니다.
알 수 없는 기존 Caddy 설정에는 덮어쓰기하지 않고 중단합니다.
실패하면 이전 설정을 복구합니다. 다음 배포에서도 이전 해시 자산을 남겨
이미 열린 탭을 깨뜨리지 않고 index.html을 마지막에 교체합니다.

복구 시 해당 백업의 Caddyfile과 compose.home.yml을 서버에 복원하고
`buzzctl start`로 Caddy 구성을 재적용합니다. 백업에 index.html이 있으면
web-client/index.html도 복원합니다. 기존 해시 자산은 남겨 둡니다.

배포 후 `/chat/`의 HTTP 200, 해시 자산의 HTTP 200, `/health`의 `ok`,
WebSocket의 AUTH challenge, 직접 로그인·상대 계정과 수신을 확인합니다.
